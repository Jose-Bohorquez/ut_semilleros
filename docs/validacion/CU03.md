## RNF03 – Seguridad en plataforma web y móvil

| Criterio medible | Estado | Evidencia |
|---|---|---|
| 0 contraseñas en texto plano; bcrypt costo 12 | ✅ | Producción: 12 de 12 hashes `$2y$12$`. `BCRYPT_ROUNDS=12` |
| Tokens Sanctum con vencimiento de 8 h | ✅ (CU01) | 8 h; 30 días solo con «Recordarme» (CU01 A2) |
| 100 % de endpoints protegidos exigen token | ✅ | `RNF03SecurityTest` recorre **todas** las rutas `api/*` y exige 401 sin token (solo 8 rutas públicas a propósito) |
| Respuestas 401/403 correctas | ✅ | Tests de roles de cada módulo + RF16 (403 `CONSENT_REQUIRED`) |
| Control de acceso por roles · validación de entradas | ✅ | Middleware `role` en cada ruta; `validate()` en cada controlador |
| Limitación de peticiones | ✅ | Límite general de la API: 120/min por usuario o IP. El login (5/min, RN14), Google (10/min) y SIA (15/min) tienen límites propios |
| Cifrado de datos personales sensibles (teléfono y dirección) | ✅ | El teléfono del coordinador se cifra en reposo (cast `encrypted`, APP_KEY) y se migraron los existentes. Los teléfonos y direcciones de los CAT son institucionales: no se cifran |
| Sin hallazgos altos en OWASP ZAP (baseline) | ✅ local · producción tras el despliegue | Frontend: 0 FAIL, 8 avisos. API: 0 FAIL; los avisos bajaron de 17 a 10 |

**Otros hallazgos corregidos:**
- La API revelaba `X-Powered-By: PHP/8.3.33`. Ya no lo hace.
- La API envía ahora `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy` y CSP `default-src 'none'`.
  Las respuestas con token van con `Cache-Control: no-store`, así el CDN nunca las guarda.
- El frontend no enviaba HSTS, `nosniff`, `X-Frame-Options`, `Referrer-Policy` ni `Permissions-Policy`.
  Ahora sí (`.htaccess`).
- **Archivos de desarrollo públicos:** `docker-compose.yml`, `Dockerfile`, `README.md`, los `*.txt` de
  arquitectura y `docs/*.md` se servían como texto. Todo está en el repositorio público, pero era
  divulgación de información. Ahora responden 404; la regla aplica solo a la raíz y no toca `SGAA/`.

**OWASP ZAP baseline (local, 2026-09-28):** 0 hallazgos altos (FAIL) en el frontend y en la API.
Avisos que quedan, todos de riesgo bajo o informativos:
- **CSP del frontend sin definir.** La SPA carga Tailwind, jQuery, DataTables, SweetAlert y Chart.js
  desde CDN y tiene un script en línea. Una CSP estricta exige inventariar todo eso primero; queda
  para una ronda propia.
- **Falta SRI en los scripts de CDN.**
- **COEP ausente.** Rompería los recursos de CDN.
- **CORS `*` en la API.** Es aceptable: la autenticación es por token Bearer, no por cookie, así que
  otro sitio no puede aprovechar una sesión. Restringirlo rompería las pruebas desde el celular en la
  red local.
- **Cabecera `Server`.** La pone el servidor o el CDN.

Corregido gracias a ZAP:
- Las cabeceras de seguridad ahora aplican a **todas** las respuestas de Laravel, no solo a `/api`:
  cubren los 404 y los errores.
- Se agregó `Permissions-Policy` en la API.

**Correcciones tras el `security-reviewer` (misma ronda):**
- **El límite de 120/min contaba por IP, no por usuario.** Corre antes de `auth:sanctum`, así que
  `$request->user()` daba null y en el Wi-Fi del campus todos los estudiantes compartían el cupo.
  Ahora resuelve el usuario desde el token (test `…keyed_by_user_not_ip`).
- **La cola `pending_revoke` guardaba tokens sin vencimiento.** Ahora guarda cada uno con su vencimiento
  y descarta los vencidos sin llamar al servidor.
- **Un 5xx del servidor sacaba el token de la cola sin revocarlo.** Ahora un 5xx o 429 se reintenta.
- **Falso positivo:** «`change()` exige doctrine/dbal en MySQL». En Laravel 12 no: la migración se
  aplicó en MySQL 9.0 local (`phone` quedó `text`, valores cifrados).

**Importante:** los teléfonos cifrados dependen de `APP_KEY`. Si el `.env` del servidor se pierde o se
regenera la clave, no se pueden leer. Hay que respaldar el `.env`.
